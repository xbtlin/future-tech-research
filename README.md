# Future Tech Research — 未来 3 年哪些新技术会火

研究窗口：**2026 – 2029**

这不是写给风险投资人的"热门赛道清单"，而是一个**持续演进的判断框架**：当新技术出现时，用一套可复用的标准给它打分，避免被 hype 带偏，也避免错过真正的拐点。

---

## 为什么是 3 年

- **< 1 年**：已经在爆发的东西，新闻里满眼都是，不用研究
- **> 5 年**：不确定性太大，多数变量今天还看不到
- **3 年窗口**：技术已经过了 demo 阶段、开始有第一批规模化应用、产业链拐点即将到来——能判断"是不是真的"而不是"是不是酷"

## 评估维度（见 `frameworks/scorecard.md`）

每项技术按五个维度打分（★1–5）：

| 维度 | 问什么 |
|---|---|
| **技术成熟度** | 从 lab demo 到量产的差距？关键瓶颈还剩几个？ |
| **经济性** | 单位成本下降曲线？什么时候跨过"能用"到"便宜到不用白不用"？ |
| **需求真实性** | 有没有付费客户？是痛点还是痒点？可证伪的销售数据？ |
| **生态成熟度** | 上下游是否齐备？标准、人才、工具链？ |
| **3 年拐点概率** | 3 年内出现规模化转折的概率（0–100%） |

---

## 研究原则（最高优先级）

- **事实先行**：数据 > 专家观点 > 媒体叙事。每个关键判断至少 2 个独立来源交叉
- **呈现正反两面**：每条预测附反面论据（"但另一方面..."），让读者自己权衡
- **可证伪**：结论写成可以被未来验证/推翻的具体命题，避免"万能正确"
- **追踪复盘**：每季度回看过往预测，错的先承认、再归因
- **拒绝赛道名词化**：不写"Web3 会起飞"，要写"XX 链上稳定币结算量 2027 年超过 $X"

## 工作流

```
新技术 → 初筛（研究框架 checklist）→ 立项 research/<tech>/
     ↓
  拉取一手数据（论文、财报、招股书、专家访谈）
     ↓
  按五维评分 → 写 3 年拐点判断 → 列反面证据
     ↓
  季度复盘（reports/YYYY-QX.md）
```

## 开始

```bash
# 新开一个技术方向
cp frameworks/scorecard-template.md research/<tech-name>/scorecard.md
```
