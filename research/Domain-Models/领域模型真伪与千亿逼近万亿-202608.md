## 0 结论摘要

1. **"领域大模型"是真命题还是伪命题，取决于你说的是哪一种。** 拆成三种：(A) 从零预训练的行业基座——已被反复证伪（BloombergGPT 被 GPT-4 反超、xAI Grok Code Fast 从零训练一年即下线、Poolside 从零训练陷入算力困境、华为 2025 年发五大行业模型 2026 年只发通用底座、智谱张鹏 2026-03 被转述称"纯粹的垂直模型是个伪命题"）；(B) 通用基座 + 领域中期训练/RL 后训练 + 与推理系统和产品闭环联合优化——是真命题，2026 年出现了一批在自己任务分布上**跑赢当期前沿模型**的实证（Cursor Composer 2.5、Cognition SWE-1.7、Intercom Fin Apex、Harvey 审阅模型、Google 内部工程模型、淘宝拍立淘、微信支付风控）；(C) 通用模型 + 领域检索/工具/harness——成立，但那不叫领域模型。**行业内正在发生的事是 A 退场、B 和 C 合流。**
2. **"领域"的正确定义不是知识领域，而是"任务分布 × 反馈信号 × 成本/延迟约束"三元组。** 金融、医疗这类知识领域不构成护城河——通用模型的知识总量永远更大（事实性知识随总参数近线性增长，见第 5 节）；构成护城河的是：私有的任务分布、可验证的反馈环境、以及前沿模型不会为你单独优化的成本/延迟点。
3. **领域模型的目标应写成一句可证伪的话**："在我方任务分布上，以 k 倍（经验值 3–10×）更低的单位成本或延迟，达到不劣于当期前沿模型的业务指标，并且这一优势在前沿模型每 3–6 个月一次的换代中可以复现。"成功不是在公开榜上赢，而是在**帕累托前沿上占住一个前沿模型不占的点**，用业务 A/B、pass^k 一致性、幻觉率、单位任务成本衡量。
4. **做好领域模型的关键按重要性排序**：私有评测先行 → 永远站在最强开源基座上（不从零预训练）→ 把私域数据变成可验证反馈环境（RL gym）而不只是语料 → 配方收敛为"中期训练 → SFT → 可验证奖励 RL → 在策略蒸馏"→ 模型架构为部署硬件设计 → 换基座的速度 → 组织上模型团队与业务团队共担业务指标。
5. **"千亿 vs 万亿"先要澄清一个前提**：2026 年的万亿模型都是 MoE（DeepSeek V4 Pro 1.6T/激活 49B、Kimi K3 2.8T/104B、Qwen3.8-Max 2.4T/95B、Inkling 975B/41B），推理成本由**激活参数 + 权重显存占用 + KV cache** 决定，不由总参数决定。100B dense 每 token 的计算量（约 200 GFLOP）反而是 Kimi K2（激活 32B，约 64 GFLOP）的 3 倍。所以"千亿更便宜"要成立，这个千亿必须是 **100–300B 总参数、10–15B 激活的 MoE**（2026 年这一档没有一家选 dense），或者比对象是同为 dense 的模型；结构性的成本优势来自"权重能装进单机 8 卡、腾出显存给 KV cache 跑大 batch、不用跨机专家并行"，且这个优势在**低并发（<数百请求/部署单元）和高交互性（>100 tok/s/user）的场景**下最大——大并发公有云上 1T MoE 反而比 100B dense 便宜 2–6 倍。
6. **理论上能否用 100B 级达到 1T 级的效果——答案分两半。** 效果要拆成"技能/推理"和"知识"两类：**技能可蒸馏、可 RL、可用测试时算力补**，2026 年的实证是 DeepSeek V4-Flash（284B/13B）与 V4-Pro（1.6T/49B）在 SWE-bench Verified 只差 1.6 分、GPQA 差 2 分；Inkling-Small（276B/12B）用在策略蒸馏后 GPQA 反超 975B 的教师 2.3 分。**知识随总参数近线性**（2–3.6 bit/参数的容量律；93 个模型 135M–1.6T 事实容量对参数量 R²=0.91；MoE 的事实量跟总参数而非激活参数），同一对模型 SimpleQA 差 23.8 分和 23.3 分，测试时算力补不了（COLM 2026 论文：14 个推理模型加算力不提 SimpleQA）。**结论：在"多个业务场景"这样一个封闭的任务分布上，用 100B 级达到 1T 级的效果理论上可行且已有先例，前提是分布内所需知识远小于 100B 的容量、长尾知识可外置到检索/工具；在开放域长尾知识上不可行，且没有已知技术能绕过。**
7. **实现的关键**：(1) 有一个更强的教师——教师已存在时蒸馏比自己 RL 省 10–100 倍算力（Qwen3：8B 在策略蒸馏 1,800 GPU 时 AIME 74.4 vs RL 17,920 GPU 时 67.6），这是 Apple 蒸馏 scaling law 明确成立的条件；(2) 在策略蒸馏 + 可验证奖励 RL 而不是离线 SFT（SFT 学一个任务掉 27.8 分其他任务，RL 只掉 3.4 分）；(3) 任务分布收敛 + 知识外置；(4) 过训练（tokens/参数远超 Chinchilla 的 20，工业界已到 500–1900）；(5) MoE 稀疏度和推理系统一起设计；(6) 私有评测。
8. **会遇到的困难**：容量鸿沟（教师太强反而学不好、≤3B 从强教师蒸馏不稳定）；多场景跷跷板（数学+代码 RL 互相 +2.6，数学+Agent 在 AIME25 上 −7.1；Qwen3-32B 经模式融合 + 通用 RL 两阶段后指令遵循 +10 但 AIME −2.4）；通用能力崩塌快于领域能力（任务专用蒸馏把 Qwen3-32B 压到 16% 参数时域内 F1 保持 0.77，MMLU 从 83.6 掉到约 25 的随机水平）；"公开榜平、实际体验差"（Cognition 自认 SWE-1.6 预览版过度思考、串行调用工具、自我循环）；教师合规风险（2026 年 2–7 月三家闭源厂商联合反蒸馏、美国财政部威胁制裁、OpenAI 关闭自助微调）；追赶周期（前沿每 3–6 个月一代，你的基座随之过时）；成本不便宜（Cursor Composer 1.5 的后训练算力已超过其基座预训练、"85% 算力用于额外训练和 RL"，训练用"数千张" B300）。
9. **时间窗口判断（我的推断）**：能力密度每 3.3–3.5 个月翻倍（Densing Law），意味着"今天 1T 的通用能力"约 11–12 个月后可以装进 100B——但这条律只在 MMLU/数学/代码类基准上拟合，不含事实性知识；前沿本身也在走。所以领域模型的优势不是"永远领先"，而是"在自己的分布上，用 5–10 倍更低成本，持续领先或持平 3–6 个月，且能随基座换代重训"。做不到"随基座换代重训"的团队，做出来的领域模型会在下一次前沿发布时归零。
10. **一句话**：领域模型的真命题形式是**"站在最强开源基座上，用私有任务分布和可验证反馈做后训练，为自己的成本/延迟点做推理协同设计"**；它的成功定义是**帕累托前沿上的一个点**，不是榜单第一；千亿逼近万亿在**封闭任务分布**上成立、在**开放长尾知识**上不成立，分界线是知识容量。

## 1 先把问题拆开

四个问题其实是一个问题的四个切面：**"通用模型的能力，有多少可以在更小的参数预算里、针对更窄的分布重新组织，且这样做在经济上划算？"**

- 问题 (1) 问的是这件事**是否存在**——有没有一个区域，专用模型在其中稳定优于通用模型的性价比；
- 问题 (2) 问的是**怎么描述那个区域**——目标函数和成功标准；
- 问题 (3) 问的是**怎么走进那个区域**——工程关键；
- 问题 (4) 问的是那个区域的**理论边界在哪**——什么能压缩、什么不能。

下面按 (1)→(2)→(3)→(4) 展开，第 5 节是本报告的核心。

## 2 领域大模型是真命题吗

### 2.1 先把"领域模型"拆成三种东西

### 2.2 B 类为什么成立：2026 年的实证记录

下面每一条都是"在自己的任务分布上与当期前沿模型的对照"，这正是问题 (4) 想要的那种证据。

**代码（最成熟的自然实验）**：

- **Cursor Composer 2**（2026-03-19，[cursor.com/blog/composer-2](https://cursor.com/blog/composer-2)，[arXiv 2603.24477](https://arxiv.org/abs/2603.24477)）：基座为 Kimi K2.5（1.04T/32B 激活 MoE，候选还有 GLM-5、DeepSeek V3.2），流程 = 继续预训练（32k→256k）+ SFT + 异步 RL，B300 GPU、MXFP8。CursorBench 61.3 / Terminal-Bench 2.0 61.7 / SWE-bench Multilingual 73.7；同表 GPT-5.4 为 63.9 / 66.5 / 76.8。价格 $0.50/$2.50 每百万 token。基座是被人从 API 路径 `kimi-k2p5-rl-0317-s515-fast` 挖出后才承认（[the-decoder 2026-03-21](https://the-decoder.com/cursor-quietly-built-its-new-coding-model-on-top-of-chinese-open-source-kimi-k2-5/)）。技术报告原话："performance on public evaluation benchmarks often correlates only loosely with the real-world utility of these models"。
- **Composer 2.5**（2026-05-18，[cursor.com/blog/composer-2-5](https://cursor.com/blog/composer-2-5)）：同一基座，25 倍合成任务 + 文本反馈 RL / 在策略蒸馏，官方称"85% of its compute goes into additional training and RL"。官方引用独立第三方 Artificial Analysis Coding Agent Index：Composer 2.5 第 3，仅次于高强度模式的 Claude Code + Opus 4.7 与 Codex + GPT-5.5，**比排在前面的两者便宜约 10–60 倍**（第三方转述的具体分数 63 vs 67/65、每任务 $0.07 vs $4.14/$4.33，本报告未能直接核实 AA 页面）。Terminal-Bench 2.0 69.3（Opus 4.7 69.4 / GPT-5.5 82.7）。
- **Cognition SWE-1.5 → 1.6 → 1.7**：SWE-1.5（2025-10-29，[cognition.com/blog/swe-1-5](https://cognition.com/blog/swe-1-5)）"数千亿参数"，官方承认基于强开源基座（社区据 tokenizer 推测 GLM-4.6，未官方确认），千卡 GB200 NVL72 做 RL，Cerebras 上 950 tok/s、13 倍于 Sonnet 4.5，SWE-Bench Pro 40.08% vs Sonnet 4.5 43.60%。SWE-1.6（2026-04-07）同底座重做后训练，SWE-Bench Pro 比 1.5 高 10% 以上、轮次 −40%——**官方在 1.6 预览版博客里承认模型存在简单问题过度思考、串行而非并行调用工具、自我循环**，即"benchmark 不差、体验差"。SWE-1.7（2026-07-08，[cognition.com/blog/swe-1-7](https://cognition.com/blog/swe-1-7)）基座明示为 Kimi K2.7 Code，"RL on top of RL"：Terminal-Bench 2.1 81.5（K2.7 72.7 / GPT-5.5 84.2 / Opus 4.8 86.9）、SWE-bench Multilingual 77.8（K2.7 73.5 / GPT-5.5 76.8 / Opus 4.8 84.4），Cerebras 1000 tok/s。**从 K2.7 到 SWE-1.7 在 Terminal-Bench 上 +8.8 分——RL 增量是真的，但同一基座别人也能拿到，护城河在数据与环境而非方法。**
- **反例**：xAI Grok Code Fast 1（2025-08-28，自称从零训练，SWE-bench Verified 70.8%，$0.20/$1.50）2026-08-15 在 OCI 按需模式退役、被通用 Grok 4.x 取代（弃用公告日期未核实）；OpenAI GPT-5-Codex（GPT-5 微调版，SWE-bench Verified 74.5 vs 72.8）→ GPT-5.3-Codex 于 2026-07-23 关停、替代型号是通用的 GPT-5.6 Sol。**当前沿厂商自己做领域特化，它最终会被吸回主线；当应用厂商做，它活在成本/延迟点上。**

**客服**：Intercom Fin Apex 1.0（2026-03-30，[opensourceforu](https://www.opensourceforu.com/2026/03/intercom-beats-frontier-ai-with-open-weights-post-training/)）：未披露的开源权重基座 + 客服转录后训练 + 基于"问题是否解决"的 RL；解决率 73.1% vs GPT-5.4 71.1% / Sonnet 4.6 69.6%，幻觉 −65%，成本约前沿模型 1/5，响应 3.7 秒。CEO 原话："Pre-training is kind of a commodity now. The frontier, if you will, is actually in post-training." 2026-06 同意被 Salesforce 以约 36 亿美元收购（待交割；公司已更名 Fin）。

**法律**：Harvey + Applied Compute（2026-08-14，[harvey.ai/blog](https://www.harvey.ai/blog/training-frontier-review-table-models-with-applied-compute)）：GLM-5.2 基座 RL 训练审阅表格模型，答案分 0.903 vs Fable 5 0.867 / GPT-5.6 Sol 0.857，每格成本比 Sonnet 5 低 54.8%。Harvey 的路径本身就是 A→C→B 的缩影：2024 与 OpenAI 合作定制判例法模型（强化微调 F1 0.563→0.677）→ 2025-05 转多模型 → 2026-06-18 宣布"用后训练开源模型逼近前沿性能"，定位与前沿模型互补。Thomson Reuters Thomson-1-Large（2026-07-31，[官方](https://www.thomsonreuters.com/en-us/posts/innovation/thomson-reuters-built-its-own-ai-model-that-now-ranks-among-the-worlds-best/)）：开源基座 + 不到 10% 的自有语料，自报 LegalBench 0.823 vs Gemini 3.1 Pro 0.843 / GPT-5.5 0.832 / Opus 4.8 0.818，PrBench Legal Hard 0.352 vs 0.293/0.333/0.315，但通用推理 0.684 vs 0.748、编码 0.399 vs 0.598——**领域指标持平前沿、通用能力明显低，是 B 类模型的典型形状**（数字全为自报，GPT-5.5 用的是非推理模式，[LawNext 复核](https://www.lawnext.com/2026/08/thomson-reuters-says-its-homegrown-ai-model-now-rivals-the-frontier-labs-i-take-a-closer-look-at-the-benchmarks.html)）。

**医疗（正反证据都有，必须一起读）**：正面是百川 M3-235B（Qwen3-235B 基座，[arXiv 2602.06570](https://arxiv.org/abs/2602.06570)，2026-02-06）HealthBench 65.1 vs GPT-5.2-High 63.3、Hard 44.4 vs 42.0，以及 Hippocratic Polaris 5.0（2026-04-30，药物安全 99.95% vs GPT-5.4 mini 87.9%——注意对照的是小模型）。反面是 Nature Medicine 2026-06-12（NYU Langone，[PubMed](https://pubmed.ncbi.nlm.nih.gov/42286322/)）"通用模型胜专用临床工具"：500 题 MedQA Gemini 3.1 Pro 97.4% vs OpenEvidence 89.6% vs UpToDate Expert AI 88.4%；100 条真实临床问题 12 名医生盲评，三个通用模型全胜，专用工具"与 Google 搜索 AI Overview 相当"。OpenEvidence 06-15 要求撤稿，06-27 出现一篇反向预印本（[arXiv 2606.28960](https://arxiv.org/abs/2606.28960)，查询取自 OpenEvidence 平台，OpenEvidence 领先 25–39 个百分点；作者独立性存疑）。**这场争议本身就是答案：领域产品能否赢，取决于评测分布由谁定义。** 更早的系统性证据偏负面：Jeong et al.（[arXiv 2411.04118](https://arxiv.org/abs/2411.04118)）3-shot 下医疗微调模型优于自身基座仅 12.1%、持平 49.8%、显著更差 38.2%；Dada et al.（[arXiv 2404.04067](https://arxiv.org/abs/2404.04067)）12 个生物医学微调模型中 9 个性能下降。

**企业内部工程**：Google "Customizing an LLM for Enterprise SE"（2026-05，[arXiv 2605.16517](https://arxiv.org/abs/2605.16517)）：万亿 token 私有 mid-training + 后训练，评价以 29,000 名开发者盲测 A/B：轮次 −23%、代码存活率 +17%——**成功定义 = 业务指标而非公开榜**。

**电商/支付/医疗**：淘宝拍立淘 MMSearch（2026-07，[arXiv 2607.17499](https://arxiv.org/abs/2607.17499)）Qwen 基座，A/B GMV +13.61%、成交 +8.21%；微信支付 SeqLLM（2026-08，[arXiv 2608.03063](https://arxiv.org/abs/2608.03063)）DeepSeek 基座、前缀式 SFT 不做继续预训练，筛查精度 92.0→97.5%、欺诈 P@Top0.01% +26.8 分；百川 M3-235B（Qwen3-235B 基座）HealthBench-Hard 44.4 超 GPT-5.2（2026-01-13）；FinGuard（2026-05，[arXiv 2605.29427](https://arxiv.org/abs/2605.29427)）Qwen3-8B SFT + 自博弈 RL 在合规任务超 Qwen3.5-397B / GPT-5.1。

### 2.3 A 类为什么失败：三条结构性原因

1. **知识不是护城河，通用模型的知识总量永远更大**。事实性知识容量与总参数近线性（第 5.2 节），行业语料只是通用语料的子集。BloombergGPT（[arXiv 2303.17564](https://arxiv.org/abs/2303.17564)，50B、约 7000 亿 token 一半金融）发布两个月后，Li et al.（[arXiv 2305.05862](https://arxiv.org/html/2305.05862)，EMNLP 2023）在同为 few-shot 的 8 个金融数据集上：FiQA-SA GPT-4 88.11 vs 75.07、ConvFinQA 76.48 vs 43.41、仅 NER 一项 BloombergGPT 领先（60.82 vs 56.71）；更难堪的是 AdaptLLM（[arXiv 2309.09530](https://arxiv.org/abs/2309.09530)）用 LLaMA-7B 做阅读理解式继续预训练后金融 5 任务均分 63.4，超过 BloombergGPT-50B 的 62.5——**7 倍参数的从零行业基座输给了通用基座 + 领域后训练**。医疗上同样：Med-PaLM 2（PaLM 2 + 医学微调）MedQA 86.5% 半年后被纯提示工程的 GPT-4 + Medprompt 90.2% 反超（[arXiv 2311.16452](https://arxiv.org/abs/2311.16452)）。Phi-4 14B 的 MMLU 84.8 但 SimpleQA 只有 3.0——推理可以小、知识不能小。
2. **领域能力的地基是通用能力**。RL 后训练的迁移证据显示数学、代码、科学互相正迁移（Guru，[arXiv 2506.14965](https://arxiv.org/abs/2506.14965)），代码 agent 的能力来自通用推理 + 工具使用，而不是代码语料本身；从零训练的行业基座缺这层地基，后训练拉不上去。DeepSeek-R1 报告表 6：同为 Qwen-32B，直接 RL AIME 47.0，从更强模型蒸馏 72.6——**"超越智能边界仍需更强的 base"**。
3. **算力与迭代速度**。Epoch（2026-04-07）：Anthropic 的算力开支超过 MiniMax 与智谱之和的 10 倍以上，蒸馏带来的"数倍"效率增益不足以抵消；一家应用公司从零预训练，等于在追赶周期上先输 6 个月（Epoch：开放权重平均落后闭源 4 个月，Lambert 2026-07 估 3–5 个月），再花一年补齐通用能力，此时前沿已经换了两代。

### 2.4 "领域"应该怎么定义

**错误定义**：按知识分（金融模型、医疗模型、法律模型）。这样定义的领域模型，护城河是语料，而语料对通用模型是可得的子集。

**正确定义（我的推断，由 2.2 的成功案例归纳）**：领域 = **任务分布 × 反馈信号 × 成本/延迟约束**：

- **任务分布**：你的流量集中在有限个任务形态上（Cursor 的编辑/补全/agent 循环、Intercom 的工单解决、Harvey 的表格审阅、支付的序列风控），且这些形态的组合是外部厂商不会为你单独优化的；
- **反馈信号**：你能给每个样本一个可验证或近似可验证的奖励（PR 是否合并、工单是否关闭、GMV 是否成交、欺诈是否命中）——这是 RL 能起作用的前提，也是私域数据真正的价值形态（不是"语料"，是"环境"）；
- **成本/延迟约束**：你的业务点在前沿模型的价格/速度曲线之外（Cursor 需要比前沿便宜 10–60 倍的每任务成本、Cognition 需要 1000 tok/s，Intercom 需要 1/5 成本和 3.7 秒）。

三个条件全满足，B 类领域模型有存在空间；缺任何一个，直接用 C 类（前沿模型 + harness）更划算。

## 3 领域模型的目标与成功标准

### 3.1 目标应写成一句可证伪的话

> "在我方任务分布 D 上，以 k 倍（k ≥ 3）更低的单位成本或延迟，业务指标 M 不劣于当期最强前沿模型，且这一优势在前沿模型换代（3–6 个月）后 T 周内可复现。"

四个变量都要事先定死：D（用真实流量抽样，不是公开基准）、k（成本或延迟倍数）、M（业务指标）、T（重训周期）。**任何一个变量说不清，项目就没有目标。**

### 3.2 成功 = 帕累托前沿上一个前沿模型不占的点

Artificial Analysis 2026-08 的数据给了参照系：前十名模型综合指数 58–63 分，价格从每任务 $0.05（GPT-5.6 Luna，52 分）到 $4.35（GPT-5.6 Sol，61 分）；Gemini 3.7 Flash（56 分、$0.40/任务、340 tok/s）被 AA 明确标为"智能-成本"与"智能-时间"双帕累托前沿。**前沿厂商自己已经在覆盖性价比前沿**，Nathan Lambert（2026-06-01）的判断是"最好的闭源实验室永远会做出给定成本下最高效的模型"，开源与领域模型的空间在"低成本、任务专用的利基"。

因此领域模型的成功不能定义为"某个通用分数更高"，而是：**在 (质量 on D, 成本, 延迟, 可控性/幻觉率, 数据闭环速度) 这个多维空间里，占住一个前沿厂商在可预见期内不会为你占的点。** Cursor 的点是每任务成本比前沿低 10–60 倍 + 与 IDE 深度耦合；Cognition 的点是 1000 tok/s；Intercom 的点是 1/5 成本 + 幻觉 −65%；Harvey 的点是每格 −54.8% 成本 + 领域评审集上 +3.6 分。

### 3.3 三个层次的成功（从低到高）

1. **成本层**：同等业务指标下成本/延迟降 k 倍——最容易做到、也最容易被前沿降价抹平（DeepSeek V4 Pro 跑完 AA 全套指数花 $604，Opus 4.7 花 $4,811，8 倍；但 2026-08-16 起 DeepSeek 峰时价格涨约 3 倍，说明便宜也不稳定）。
2. **能力层**：在 D 上业务指标超过前沿模型——需要私有反馈环境，是真护城河；Intercom、Harvey、Google 内部模型属于此层。
3. **闭环层**：业务数据 → 评测 → 训练 → 部署的迭代周期短于前沿换代周期，且能换基座重训——只有做到这一层，成功才是可持续的。Cursor 从 Composer 1（2025-10）到 2.5（2026-05）七个月四个版本、中间换了基座，是这一层的样板。

### 3.4 什么算失败

- 公开榜追平但业务 A/B 不涨（Cursor 技术报告和 Cognition 都自陈过这一现象）；
- 前沿模型下一版发布后，领域模型的优势归零且团队没有能力在 T 周内重训；
- 领域指标涨、通用能力崩，导致长尾请求体验劣化（第 5.6 节有量化）；
- 单位成本优势小于 3 倍——这个数字以内，前沿厂商一次降价就能抹平（GPT-5.6 Terra 2026-07-30 降价 20%，Sonnet 5 上市价 $2/$10）。

### 3.5 评测怎么建

Anthropic《Demystifying Evals for AI Agents》（2026-01-09，[链接](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)）的做法可以直接抄：从真实失败案例起步 20–50 题；代码/模型/人工三类评分器；同时报 pass@k 与 pass^k（单次 75% 的任务连续三次全对只有 42%——业务上关心的是后者）；两位专家独立判定一致才收；接近 100% 即换题。加一条本报告的建议：**评测集必须与训练团队隔离，且每次前沿模型发布后先跑前沿模型再跑自己**，否则会出现《The Leaderboard Illusion》（[arXiv 2504.20879](https://arxiv.org/abs/2504.20879)）里 Meta 私测 27 个变体挑最好的那种自我欺骗。

## 4 做好领域模型的关键

按重要性排序，每条附证据。

**关键 1：评测先行，且是业务评测**。见 3.5。Google 内部模型用 29,000 开发者盲测；淘宝用 GMV；微信支付用欺诈命中率。没有这一步，后面所有训练都是在优化一个不知道对不对的目标。

**关键 2：永远站在最强开源基座上，不从零预训练**。2.2 的全部成功案例基座都来自通用大模型（K2.5、K2.7、GLM-5.2、Qwen、DeepSeek）；仅有的两个从零训练案例（GCF-1、Poolside）一个被弃、一个陷困境。Apple 蒸馏 scaling law（[arXiv 2502.08606](https://arxiv.org/abs/2502.08606)）的结论正是"给足算力时监督预训练总优于蒸馏，但**教师已存在或有多个学生时蒸馏划算**"——对应用公司来说教师永远已存在。开源基座与闭源顶级的差距 2026-08 为 AA 指数 3 分（63 vs 60）、Epoch 估 4 个月，足够用。

**关键 3：把私域数据变成"环境"而不是"语料"**。领域继续预训练的收益是有的但有限（NVIDIA "Reuse, Don't Retrain"：15B 模型 +300B token 平均 +9%；Instruction Pre-Training：Llama3-8B 领域 CPT 生物医学 58.4→61.3、金融 72.0→74.7）；真正拉开差距的是 RL 用的可验证反馈：Composer 2.5 用 25 倍合成任务 + 文本反馈，Intercom 用"是否解决"，Harvey 用审阅评分。Kimi K2 报告的做法（3000+ 真实 MCP 工具 + 20000+ 合成工具轨迹）说明环境是可以合成的。**Jason Wei 的 verifier's rule：可验证程度决定可训练性**——领域团队最该投入的不是标数据，是建验证器。

**关键 4：配方已收敛，照着做**：
- 中期训练：领域数据占 70–90%、通用回放 10–30%（偏移越大回放越多；Ibrahim et al. [arXiv 2403.08763](https://arxiv.org/abs/2403.08763)：弱偏移 5% 回放即接近联合训练，强偏移需 25%）；学习率从预训练末值起、不回到原峰值；把原始领域语料改写为 QA/阅读理解格式可同时保通用能力（AdaptLLM：原始语料 CPT 反而伤 prompting，生物医学 44.2→41.7；改写后 47.3 且通用不降）；固定算力下 mid-training 显著优于纯 RL（[arXiv 2512.07783](https://arxiv.org/abs/2512.07783)）。
- SFT 只做冷启动，别指望它学能力：《Retaining by Doing》（[arXiv 2510.18874](https://arxiv.org/abs/2510.18874)）SFT 学 IFEval +25.2 伴随其他任务 −27.8，RL +18.4 只掉 3.4；MMLU 任务 SFT −38.5 vs RL −0.2。
- 多场景 RL：主流已从"多阶段"转向"各场景专家分别 RL → 蒸馏 → 单阶段混合 RL"（DeepSeek V3.2、GLM-4.5、Kimi K2 一致），M2RL（[arXiv 2602.12566](https://arxiv.org/abs/2602.12566)）显示混合 RL 用 63.7% GPU 时达到合并水平。
- 在策略蒸馏是 2026 年的杀手锏：Qwen3 8B 用 1,800 GPU 时达到 RL 17,920 GPU 时的效果还更好（74.4 vs 67.6）；Thinking Machines 报告比 SFT 省 9–30 倍、比 RL 省 50–100 倍；Inkling-Small 用它反超教师；2026-08 两周内 arXiv 至少 10 篇在策略蒸馏论文，Intern-S2（397B）也用它。

**关键 5：模型架构为部署硬件设计**。Cognition 选"数千亿参数"的 MoE 并把它放到 Cerebras 上跑 1000 tok/s；Cursor 用 MXFP8 在 B300 上做异步 RL；OpenAI 出 GPT-5.3-Codex-Spark 专门在 Cerebras 上跑 >1000 tok/s。速度本身是产品能力——SWE-1.5 的 13 倍速让 agent 循环从"等"变成"看"。激活参数量、专家数、量化精度、KV cache 结构都应该在立项时就对着目标硬件定，不是训完再压。

**关键 6：换基座的速度**。Cursor 七个月四版、中间换基座；Cognition 从推测的 GLM-4.6 换到 K2.7；OpenAI 关闭自助微调（2026-05-07 起不对新组织开放，2027-01-06 停止）、Anthropic 微调文档下线，意味着**依赖闭源厂商微调服务的路线已被关掉，开源基座 + 自有训练栈是唯一可持续的路线**。训练栈要做到"新基座出来两周内可以复训"——这决定你的领域模型是资产还是一次性消耗品。

**关键 7：组织**。模型团队要背业务指标，业务团队要产出可验证反馈。Google 内部模型和 Intercom 的共同点是训练团队与产品团队共用一套 A/B 系统。

## 5 千亿 vs 万亿：理论上能否实现

### 5.1 先澄清前提：万亿是 MoE，成本不由总参数决定

2026 年的"万亿模型"全部是 MoE：

| 模型 | 总参数 | 激活参数 | 稀疏比 | 定价（$/M 输入-输出） | AA 指数 |
|---|---|---|---|---|---|
| DeepSeek V4 Pro（2026-04） | 1.6T | 49B | 3.1% | $0.435 / $0.87（峰时起 $1.32 / $3.96） | 53 |
| DeepSeek V4 Flash | 284B | 13B | 4.6% | $0.14 / $0.28 | 52 |
| Kimi K3（2026-07） | 2.8T | 104B | 3.7% | $3 / $15 | ≈60 |

2026 年新模型的稀疏比已收敛到 3–5%（1/20–1/32）：旗舰总参数上探 1.6T–2.8T、激活 50–105B；中档统一在 100–300B 总参 / 10–13B 激活（V4-Flash 284B/13B、Inkling-Small 276B/12B、Nemotron 3 Super 120B/12B、Qwen3.5-122B/10B、GLM-4.5-Air 106B/12B）。**没有一家在 100–300B 这一档选 dense。**

推理成本的物理决定因素是三层叠加（数据来自各厂公开账本与 SemiAnalysis InferenceX，2026-08 抓取）：

- **第一层：每 token 计算与带宽 ≈ 激活参数**。每 token 前向 FLOPs ≈ 2 × 激活参数：100B dense ≈ 200 GFLOP，Kimi K2 ≈ 64，DeepSeek V4 Pro ≈ 98，V4 Flash ≈ 26。decode 阶段是内存带宽受限——每步要把激活的权重和全部 KV cache 读一遍。**一个 100B dense 的每 token 计算量是 1T MoE 的 2–3 倍。**
- **第二层：总参数决定最小部署单元与固定成本**。1T FP8 ≈ 1 TB 权重，至少 8 张 141GB 卡只放权重、实际要跨机专家并行（DeepSeek V3/R1 生产集群 decode 用 EP144 = 18 个节点，[open-infra-index Day 6](https://github.com/deepseek-ai/open-infra-index)，2025-03-01）；100B FP8 ≈ 100 GB，单机 8 卡放下后还有 500+ GB 给 KV cache——**KV cache 空间决定能开多大 batch，batch 决定利用率，利用率决定每 token 成本**。这是"小总参数"最结构性的优势。
- **第三层：MoE 只在大并发时兑现"激活小"的优势**。带宽临界批量在 H100 上约 280 token/步（[JAX scaling book](https://jax-ml.github.io/scaling-book/inference)），MoE 把它抬高 E/k 倍——V3 的 256/8 = 32 倍，每副本要约 9,000 token/步才进入算力受限区，这就是 DeepSeek 必须 EP144 + 上万并发的原因。**并发不足时每步仍要读全部专家，等于按总参数付带宽**——私有化部署、低 QPS 场景下 1T MoE 的成本优势消失，100B 级的优势放大。
- **交互性（每用户 tok/s）是成本的乘数**：InferenceX 实测 R1 在 B200 上 42 tok/s/user 时 $0.10/M 输出、100 tok/s/user 时 $0.97/M——**交互性每翻倍，成本呈数量级上升**；V4-Pro 1.6T 在 B200 上 61 tok/s/user 时 $0.07/M，GB300 + MTP 后 $0.156/M（InferenceX 是交互式仪表盘，这组数字由本轮检索读取、未能二次核实；趋势与 DeepSeek 自己公布的账本一致）。低延迟要求越高，激活参数小的优势越大。
- **市场价印证与反例**：OpenRouter 2026-08-15 中位价（13 家 provider）——671B/37B 的 DeepSeek V3.2 输出 $0.42 低于 70B dense（Llama 3.1-70B 中位 $0.72、最低 $0.40）；117B/5B 的 gpt-oss-120b 中位混合价约 $0.26、最低约 $0.065，是 70B dense 的 1/3 到 1/6；**但 1T/32B 的 Kimi K2 输出价 $2.50 反高于 70B dense——因为只有一家 provider、最低 8×H200 起步的固定成本无人摊薄，不是激活参数决定的**。速度上，1T–2.8T 级 MoE 普遍只有 40–90 tok/s，并不比 70B dense 快；只有 5B 激活的 gpt-oss 明显快（Cerebras 1,731、Groq 476 tok/s）。DeepSeek V4 Pro（1.6T/49B）与 Flash（284B/13B）总参数差 5.6 倍、激活差 3.8 倍，价格差 3.1 倍，AA 指数只差 1 分。
- **稀疏度不是免费的**：Tian et al.（[arXiv 2507.17702](https://arxiv.org/abs/2507.17702)）的"效率杠杆"（Efficiency Leverage）约 7 倍——0.85B 激活的 MoE ≈ 6.1B dense；Kimi K2 报告同 loss 下稀疏 48 比稀疏 8 省 FLOPs 1.69 倍；Apple（[arXiv 2501.12370](https://arxiv.org/abs/2501.12370)）最优稀疏度随算力上升但阅读理解类下游迁移较差；2026 年论文（[arXiv 2601.08215](https://arxiv.org/abs/2601.08215)）建议"最大化总参、最小化激活"。**"1T 总参 / 100B 激活 ≈ 1T dense"没有任何文献支持**；按杠杆律外推，100B 总参 / 10B 激活的天花板约等效 60–80B dense（外推，未核实）。
- **降本技术已成标配**：FP4/NVFP4 几乎无损（R1 MMLU 90.8→90.7），GB200 上 NVFP4 GEMM 1.9 倍；MTP/推测解码 1.8 倍（V3 接受率 85–90%）、EAGLE-3 最高 6.5 倍、GB300 上 150 tok/s/user 开 MTP 后 $2.35→$0.11/M——但**大 batch 时收益递减**（128×H200 仅 +14%）；MLA 把 KV 减 93.3%；DSA 稀疏注意力把 128K 处 decode 从 $2.15 降到 $0.25/M。这些对 100B 与 1T 都适用，不改变相对关系。
- **自建 vs API 的临界点是利用率而非日 token 量**：自建 Llama-70B 4×H100 约 $1.24/M，85% 利用率下 $0.62/M ≈ Groq API 价（spheron，2026-07-22）。DeepSeek 自己的一日账本：$2/卡时 → 日成本 $87,072，按 R1 定价理论日收入 $562,027、理论利润率 545%——**只有把集群填满，1T MoE 才便宜**。

**结论**：如果目标是"比万亿 MoE 便宜、快"，这个"千亿模型"应该是 **200–300B 总参数、10–15B 激活、稀疏比 1/20–1/25 的 MoE，配 MLA/DSA 或线性混合注意力、原生 FP4/MXFP4 + MTP**（即 V4-Flash / Inkling-Small / Nemotron Super 这一档），而不是 100B dense；dense 只在 ≤30B（Qwen3.6-27B、Gemma 4 31B）或极低并发/边缘场景合理。同等质量下，大并发（万级并发、EP 部署）时 1T MoE 反而比 100B dense 每 token 便宜 2–6 倍；**反转条件是 (a) 并发 < 数百请求/部署单元，(b) 要求 >100 tok/s/user 的低延迟，(c) 长上下文 >128K 时 KV 而非权重主导**——而 (a)(b) 恰恰是多数企业私有部署和 agent 场景的常态。**问题 (4) 中"千亿更便宜更快"只有在这个前提下才成立。**

### 5.2 把"效果"拆成两半：技能与知识

这是本报告最重要的一节。"效果等同"能否实现，取决于效果里有多少是**技能/推理**、多少是**事实性知识**。

**技能可以压缩、蒸馏、用 RL 和测试时算力补**：

- 同系列大小模型在推理/代码基准上差距很小（数据来自各模型卡/技术报告，2026-08 抓取）：DeepSeek V4-Flash 284B/13B vs V4-Pro 1.6T/49B：SWE-bench Verified 79.0 vs 80.6（−1.6）、GPQA 88.1 vs 90.1（−2）、HMMT26 −0.4；GPT-5.6 Luna/Terra vs Sol：GPQA −2.3/−1.7、SWE-Bench Pro −1.9；Gemini 3 Flash vs Pro：GPQA −1.5、SWE-bench +1.8；Sonnet 4.6 vs Opus 4.6：GPQA −1.4、SWE-bench Verified −1.2。
- **Inkling-Small（276B/12B）用在策略蒸馏 + 2 周 RL 后 GPQA 89.5 反超 975B/41B 的教师 87.2、SWE-bench Verified +2.6、HLE 31.6 > 29.7**（[thinkingmachines.ai/news/inkling-small](https://thinkingmachines.ai/news/inkling-small/)，2026-07-30）——学生在技能上可以超过教师。
- 参数复用（循环/递归深度）可以提升推理而不加参数：Ouro（[arXiv 2510.25741](https://arxiv.org/abs/2510.25741)）1.4B/2.6B 在推理上追平 12B。
- 测试时算力：Snell et al.（[arXiv 2408.03314](https://arxiv.org/abs/2408.03314)）小模型 + 算力最优的测试时策略在易/中等难度题上可胜 14 倍大模型（但推理 token 远少于预训练 token、且题目不是最难时才成立）。

**知识随总参数近线性，压缩不了**：

- 容量律：充分训练时约 2 bit/参数（Allen-Zhu & Li Physics 3.3，[arXiv 2404.05405](https://arxiv.org/abs/2404.05405)；每条知识需约 1000 次曝光，100 次降到 1 bit；int8 不损、int4 降到 0.7）；Morris et al.（[arXiv 2505.24832](https://arxiv.org/abs/2505.24832)，ICML 2026 荣誉提名）总记忆容量约 3.6 bit/参数。口径不同但量级一致：**100B 与 1T 的事实容量差约 10 倍，架构、量化、循环都补不回来。**
- 与激活参数无关：《Incompressible Knowledge Probes》（[arXiv 2604.24827](https://arxiv.org/abs/2604.24827)，2026-04）93 个开源模型 135M–1.6T 事实容量对参数量 R²=0.91；MoE 的事实量跟总参数（R² 0.67）而非激活参数（0.41）。Nakamura《Optimal Sparsity of MoE》（[arXiv 2508.18672](https://arxiv.org/abs/2508.18672)，ICLR 2026 oral）：记忆任务随总参数单调增益，推理任务受 tokens/参数约束，**RL 与测试时算力都不改变此趋势**。
- 实测（大−小，百分点）：V4-Flash vs V4-Pro SimpleQA-Verified 34.1 vs 57.9（−23.8）；Inkling-Small vs Inkling 20.6 vs 43.9（−23.3）；GLM-4.5-Air 106B vs 355B 14.5 vs 26.4；Sonnet 5 vs Opus 5 / Fable 5（AA-Omniscience）40.1 vs 60.9 / 65.3；GPT-5.6 Luna/Terra vs Sol 42.7/46.8 vs 59.4；Gemini 2.5 Flash vs Pro 26.9 vs 54.0。**规律：降一档 SimpleQA 掉 10–45 点，GPQA 掉 1–5 点，SWE-bench 通常 <4 点。**
- 测试时算力救不了知识：《Test-Time Scaling in Reasoning Models Is Not Effective for Knowledge-Intensive Tasks Yet》（[arXiv 2509.06861](https://arxiv.org/abs/2509.06861)，COLM 2026）14 个推理模型加算力不提 SimpleQA，GPT-5-mini 幻觉反升 >15%——信息论上算力不能注入新信息；Phi-4 14B MMLU 84.8 但 SimpleQA 3.0。

**同一对模型上"技能几乎不差、知识差一大截"，这就是问题 (4) 的边界。**

### 5.3 理论可行的条件

把上面的证据合起来，"100B 级在多个业务场景上等同于 1T 级"在以下条件同时满足时理论上可行，且 2026 年已有先例（V4-Flash、Inkling-Small、Composer 2.5、SWE-1.7、Fin Apex）：

1. **任务分布是封闭的**：k 个业务场景的并集所需的事实性知识远小于 100B 的容量（按 2 bit/参数即约 200 Gbit ≈ 25 GB 的"可提取事实"，够装下任何一个行业的结构化知识，装不下开放世界）；
2. **长尾知识可以外置**：检索、工具、数据库——Karpathy 的"cognitive core"论（几 B 参数的推理核 + 外置事实）和《Knowledgeless LMs》（[arXiv 2607.12831](https://arxiv.org/abs/2607.12831)，2026-07：匿名实体预训练降低闭卷召回、RAG 场景 +20–25%）指的是同一件事；
3. **有可验证反馈**：RL 与在策略蒸馏都需要它；没有验证器的场景（开放写作、主观判断）小模型追不上；
4. **有更强的教师**：蒸馏比自己 RL 省一到两个数量级算力，且学生可以在技能上反超教师；
5. **过训练**：tokens/参数远超 Chinchilla 的 20（工业界：Llama 3 8B 约 1,875、Gemma3-27B 约 520、Qwen3 36T token），推理最优规模律（Sardana & Frankle [arXiv 2401.00448](https://arxiv.org/abs/2401.00448)：考虑推理量后应把 30B 换成 13.6B × 2.84 倍数据）与考虑采样成本的 T² 规模律（[arXiv 2604.01411](https://arxiv.org/abs/2604.01411)）都支持"小而过训"；
6. **等同的定义是业务指标而非通用榜**：Composer 2.5 在 AA Coding Agent Index 排第 3、只落后前两名的高强度模式，但每任务成本低 10–60 倍。

### 5.4 定量估算（我的推断，明确标注）

- **技能追平所需时间**：Densing Law（[arXiv 2412.04315](https://arxiv.org/abs/2412.04315)；Nature MI 2025 版更新为 3.5 个月倍增）意味着"今天 1T 的通用能力密度"约 log₂(10) × 3.3–3.5 ≈ 11–12 个月后可装进 100B。这条律只在 MMLU/BBH/数学/代码上拟合，不含 SimpleQA，所以只对技能成立。
- **在封闭分布上追平所需时间远短于此**：Composer 从 1 到 2.5 用了 7 个月；Cognition 从 SWE-1.5 到 1.7 用了 8 个月；Inkling-Small 从教师发布到反超教师用了 2 周（在策略蒸馏 + 2 周 RL）。**只要教师存在，追平不是时间问题，是数据与验证器问题。**
- **成本**：训练美元数没有任何一家披露。已知：Composer 1.5 的后训练算力超过其基座的预训练、Composer 2.5"85% 算力用于额外训练和 RL"、Cursor "数千张 GPU"、Cognition 千卡 GB200 NVL72、Grok 4.5 联训用数万 GB300；DeepSeek V3 从零预训练 2.788M H800 时（$5.6M，2024-12）是最后一个公开的数字，Lambert（2026-04-11）估"训练有意义的模型正在从数百万美元转向数十亿美元"。**结论：后训练一个 100B 级 MoE 到前沿水平的算力量级不低于其基座预训练，是千卡到万卡级项目。**
- **推理成本比**：按 5.1，100–300B 级 MoE（10–15B 激活）对 1T–3T MoE（40–105B 激活）每 token 计算量省 3–7 倍，显存省 4–10 倍，加上单机部署带来的 batch 提升与低延迟点上的交互性红利，**公有云大并发下每 token 成本 3 倍左右（V4 Flash vs Pro 实价 3.1 倍），私有部署 / 低并发 / 高交互性场景 5–10 倍是合理预期**；含 harness 联合优化后可以更夸张（Composer 2.5 官方称比排在前面的高强度前沿模式每任务便宜 10–60 倍）。速度上要注意：1T–3T MoE 在主流 GPU 上只有 40–90 tok/s，中档 MoE 120–290 tok/s，上 Cerebras/Groq 类推理芯片后 950–1,700 tok/s——**"更快"的来源主要是激活参数小 + 专用硬件，不是总参数小本身**。

### 5.5 实现的关键（问题 4 的第二问）

1. **教师**：找到并锁定一个比目标强的教师，合规地获得其输出（见 5.6 合规风险）。Apple 蒸馏律：最优教师略大于学生后即平台，教师太强反而有"能力鸿沟"——教师不必是最强，要"够强且思维模式兼容"（[arXiv 2604.13016](https://arxiv.org/abs/2604.13016)：在策略蒸馏成功条件 = 师生思维模式兼容 + 教师提供真正新能力）。
2. **在策略蒸馏 + 可验证奖励 RL**，不是离线 SFT。SFT 只做冷启动。
3. **任务分布收敛与知识外置同时做**：把开放域知识请求路由到检索/工具/更大模型（路由本身也是一个可训练的小模型），让 100B 只负责它擅长的技能。
4. **数据配比按 D-CPT / CMR 律定**：领域 70–90%、通用回放 10–30%；多场景 RL 各场景先分别训到收敛再蒸馏合并、最后单阶段混合 RL；用容量竞争律（[arXiv 2606.08167](https://arxiv.org/abs/2606.08167)，ICML 2026）而不是拍脑袋分配场景配额。
5. **架构对着硬件定**：总参数由目标显存反推（单机 8 卡 FP8 → ≤300B 总参数最舒服）、激活参数由目标延迟反推、专家粒度按 fine-grained MoE 规模律；MTP/推测解码、KV 量化、前缀缓存在立项时就进设计。
6. **私有评测 + pass^k + 幻觉率** 作为唯一成功标准；每次前沿发布先跑前沿。

### 5.6 会遇到的困难（问题 4 的第三问）

按发生概率排序：

1. **多场景跷跷板**。这是最确定会遇到的。M2RL（[arXiv 2602.12566](https://arxiv.org/abs/2602.12566)，2026-02）Qwen3-4B 五域：数学+代码 RL 互相 +2.63（AIME24），数学+Agent 在 AIME25 上 −7.11；更隐蔽的是，多域混合 RL 后模型对 IFEval 的**过程验证能力**从单域 RL 的 64.2 崩到 27.5（合并法 79.1），而生成分仍有 93.5——按生成分看不出问题；Qwen3-32B 经思考模式融合 + 通用 RL 两阶段后 ThinkFollow 88.7→98.9 但 AIME'24 83.8→81.4、LiveCodeBench 68.4→65.7（官方承认负迁移）；《Can One Domain Help Others?》（[arXiv 2507.17512](https://arxiv.org/abs/2507.17512)）数学 RL 对代码 −6.86、对谜题 +14.0，数学+谜题混合对代码 −22.6；Guru：难数学域内 +2.8–6.3% 但跨域 −3 到 −9.2%。**推理型场景之间互相正迁移，冲突集中在推理 vs 对话/指令遵循/写作**——业务场景越杂，这个问题越重。缓解手段：专家分训再蒸馏（DeepSeek V3.2）、课程顺序（Omni-Thinker Code→Math→QA→Writing 比联合 +6.2%）、梯度手术（[arXiv 2602.02301](https://arxiv.org/abs/2602.02301) +4.3）、MoE 隔离（Branch-Train-MiX 各域不回退，占 23% 算力）。
2. **通用能力崩得比领域能力快**。《Scaling Laws for Task-Specific LLM Distillation》（[arXiv 2606.24747](https://arxiv.org/abs/2606.24747)，2026-06）：Qwen3-32B-Base 压到 16% 参数（5.24B）时域内 Macro F1 保持 0.77，MMLU 从 83.6 掉到 25.5–26.4（随机水平）、MMLU-Pro 65.5→8–10；50% 参数时 MMLU 也只剩 40–55——原文"general-knowledge benchmarks collapse well before the same point"。Control LLM 报告 CPT 基线 MMLU 退化 >35%。这在业务上的表现是：主路径漂亮、长尾请求胡说，用户对后者的记忆更深。缓解：回放、on-policy 数据、10% 在策略回放可把遗忘降 46%（[arXiv 2605.29495](https://arxiv.org/abs/2605.29495)）。
3. **"公开榜平、实际体验差"**。Cognition 官方承认 SWE-1.6 预览版过度思考、串行调用工具、自我循环；社区报告 Composer 2/2.5 长任务鉴权/后端逻辑掉链子；Cursor 技术报告自陈公开基准表现与真实效用"often correlates only loosely"。根因是评测分布与流量分布不一致 + 小模型把容量集中在易样本、放弃难尾（[arXiv 2603.07365](https://arxiv.org/abs/2603.07365)）。缓解：pass^k、真实失败驱动的评测集、长任务评测。
4. **容量鸿沟**。教师太强反而学不好（Apple 蒸馏律的折断幂律）；≤3B 从强教师蒸馏不稳定（[arXiv 2502.12143](https://arxiv.org/abs/2502.12143)）；CoT 蒸馏有时低于学生蒸馏前基线（[arXiv 2604.08880](https://arxiv.org/abs/2604.08880)）。100B 级离这个下限较远，但选教师时仍要"略强"而非"最强"。
5. **教师的合规风险（2026 年新增、且在加剧）**。2026-02-23 Anthropic 公布检测到约 24,000 个欺诈账号、1,600 万次交互用于蒸馏（[链接](https://www.anthropic.com/news/detecting-and-preventing-distillation-attacks)）；04-07 OpenAI/Anthropic/Google 联合共享反蒸馏情报；06-25 Anthropic 指控阿里 25,000 账号 2,880 万次交互；07-22 白宫指控月之暗面蒸馏 Fable 5 训练 K3，财政部长称"制裁与实体清单在选项之内"（专家质疑时间线，中方否认）；Anthropic 消费者条款禁止用输出"develop or train any AI or ML models"，2025-09 起限制中资控股 >50% 实体。**闭源前沿模型作为教师这条路在合规上已经很窄，可行的教师是开源前沿（K3、DeepSeek V4、Qwen3.8、GLM-5.2、Inkling）——它们与闭源顶级的差距是 AA 3 分 / 3–5 个月，够用。** OpenAI 关闭自助微调、Anthropic 微调下线，也把"闭源厂商替你训"这条路关了。
6. **追赶周期**。前沿模型 2026 年上半年发布节奏：GPT-5.5（04）→ 5.6（07）；Fable 5（06）→ Opus 5（07）；Gemini 3.1 Pro（02）→ 3.7 Flash（08）；DeepSeek V4（04）；Kimi K3（07）。约 3 个月一代。你的领域模型每次基座换代都要评估是否重训，重训成本以千卡·月计。做不到自动化流水线的团队追不上。
7. **训练成本与稳定性**。后训练算力 ≥ 基座预训练；大规模 RL 的工程坑（训推数值不一致、MoE 路由一致性）本仓库另一份综述已详述（[自动后训练综述](../Post-training/自动后训练综述-202608.md)）。
8. **过训练基座更难微调**。《Overtrained LMs Are Harder to Fine-Tune》（[arXiv 2503.19206](https://arxiv.org/abs/2503.19206)）OLMo-1B 3T 版比 2.3T 版微调后差 >2%——选基座时"训得最多"未必"最好改"，要小规模先试。
9. **便宜也不稳定，且要在自己的算力上算**。DeepSeek 2026-08-16 起峰谷定价、峰时涨约 3 倍；GPU 租价 B200 同比涨 11%；自建 vs API 的临界点是利用率而非 token 量（85% 利用率的自建 70B ≈ Groq API 价）。你的成本优势要在自己的算力、自己的并发曲线上算——一个只有几百并发的私有部署，1T MoE 的"激活小"根本兑现不了（5.1 第三层），这时 100B 级的优势才是真的；反过来，如果业务是公有云上的万级并发，前沿厂商的 1T MoE 每 token 可能比你的 100B dense 还便宜。
10. **架构选错就全盘皆输**。2026 年 100–300B 档全部是 MoE + 10–15B 激活 + 稀疏/线性注意力 + 原生 FP4；如果为了"每 token 想得深"选了 100B dense，每 token 计算量是 1T MoE 的 2–3 倍，"更便宜"直接不成立，只剩显存和部署简单这两项优势。

### 5.7 哪些地方 100B 追不上 1T——诚实清单

- 开放域长尾事实问答（SimpleQA 类）：差 20 分以上，且是结构性的；
- 多语言/多领域同时覆盖：容量竞争律说明每多一个域都在挤别的域；
- 极难推理题（AIME/HLE 最难档）：Snell 的结论是"最难题几乎无收益，应扩预训练"；
- 需要"没见过的领域也稳"的通用 agent 场景：小模型放弃难尾的倾向在此暴露；
- 主观、无验证器的场景（开放写作、审美）：RL 与蒸馏都缺信号。

## 6 一条可操作的路线（如果要做）

以下是本报告的建议，不是任何一家的公开配方，但每一步都对应第 4–5 节的证据。

```
第 0 步（1 个月）  私有评测：从真实失败抽 200–500 题/场景，pass^k + 幻觉率 + 业务指标；
                  先跑当期前沿模型建立基线，定 D / k / M / T 四个变量
第 1 步（并行）    基座选型：开源前沿 MoE，总参数由"单机 8 卡 FP8 放下 + KV 余量"反推（≤300B），
                  激活 10–20B；小规模试微调（避开"过训练难微调"的坑）
第 2 步（1–2 月）  中期训练：领域数据改写为 QA/阅读理解 + 通用回放 10–30%，LR 从预训练末值起；
                  同时建每个场景的验证器/环境（这是最贵也最值的一步）
第 3 步（1–2 月）  各场景分别 RLVR 到收敛 → 在策略蒸馏合并 → 单阶段混合 RL；教师用开源前沿
第 4 步（持续）    路由：开放域/长尾请求送检索、工具或更大模型；100B 只接自己擅长的
第 5 步（持续）    推理系统：MTP/推测解码、KV 量化、前缀缓存、目标硬件（含专用推理芯片）
第 6 步（每 3 月）  前沿换代复评：先跑前沿再跑自己；差距 <k 倍成本优势即启动重训或退回 C 类
```

**退出条件写在前面**：如果两轮换代后成本优势 <3 倍、或业务指标从未超过前沿模型、或团队做不到 T 周内重训，退回"前沿模型 + harness"（C 类）——那不是失败，那是 2.4 的三个条件不满足。

## 7 反面论据与未定论

- **"前沿厂商会把性价比前沿全占了"**：Gemini 3.7 Flash（56 分、$0.40/任务、340 tok/s）、GPT-5.6 Luna（52 分、$0.05/任务）说明他们确实在占。反驳：他们占的是通用分布上的性价比点，不是你的分布；Intercom/Harvey 在自己分布上仍赢了。但这个空间在收窄，SemiAnalysis（2026-05）称模型实验室"正在拿走全部价值"、Anthropic 毛利从 <40% 升到 >70%。
- **"开源基座会不会断供"**：Meta 已转闭源（Muse Spark），Thinking Machines 的 Inkling 只走 Tinker 不卖 API；但中国开源阵营（DeepSeek、Kimi、Qwen、GLM、MiniMax、美团、蚂蚁）2026 年供给充足且 MIT/Apache 许可。风险在地缘：美方 2026 年 4–7 月对"蒸馏"的指控可能延伸为对开源权重的限制，Anthropic 07-27 表态"从未主张禁止开源权重"但支持打击"工业规模蒸馏"。
- **"蒸馏是灰色地带"**：Lambert 2026-05："蒸馏是行业标准技术，一直是灰色地带"；07-12："在这个时点上蒸馏基本是一场监管俘获运动"。本报告立场：用开源前沿做教师在许可上是干净的，用闭源输出做教师看 ToS——多数已禁止。
- **"领域产品输给通用模型"的证据可能是评测分布偏差**：Nature Medicine 2026-06 那篇用 MedQA + HealthBench 让通用模型大胜 OpenEvidence，反向预印本用 OpenEvidence 平台上的真实床旁问题让 OpenEvidence 大胜 25–39 分。两边都有立场，但它们共同说明：**离开"谁定义评测分布"，领域模型的胜负没有意义**——这也是第 3 节把"评测先行"排第一的原因。
- **B 类模型的自报数字要打折**：Thomson-1-Large 全部自报且对照的 GPT-5.5 用非推理模式；Kimi K2.7-Code 只发自家 benchmark；Cursor/Cognition 均未在 SWE-bench Verified 上给独立成绩。本报告用的 Composer 2.5（AA Coding Agent Index）和 Nature Medicine 是少数第三方数字。
- **中国的路径可能不同**：Lambert（2026-05-07）："几乎每家中国大型科技公司都在训自己的通用模型……美国对应的公司只会买服务"。国内 2026H1 招标中应用类中标 2,770 个占 60.7%、金融 406 个同比 +110%，但"自研基座 vs 通用底座后训练"的比例没有公开数据；沙丘智库报告银行大模型采用率 53.5% 也没拆这一项。本报告的 A/B/C 判决对国内是否成立，取决于算力自主与合规约束，不完全是技术问题。
- **未定论**：(a) 一个模型多业务 vs 多个小模型的服务成本一手对比，本轮没检到；(b) "公开榜高但业务 A/B 不涨"只有间接证据，没有受控对照；(c) 2026 年"从 ≥400B 剪到 100B 保留 X%"的明确数字未检到；(d) Densing Law 是否在知识任务上失效没有论文直接检验；(e) Grok 4.5"1.5T 从零预训练"、SWE-1.5 基座 GLM-4.6、Grok 5 6T、OpenEvidence 自研模型、Hippocratic 700B 是否从零训练，均为二手或社区推测，未核实；(f) "100B 总参 / 10B 激活 ≈ 60–80B dense"是按效率杠杆律外推，未核实。
